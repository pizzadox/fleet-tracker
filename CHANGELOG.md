## [1.7.7-beta] — 2026-05-25

### Уведомления о синхронизации

- **Умные toast-уведомления** о результате синхронизации:
  - 🟢 Зелёный `success` — только при 100% успешной синхронизации всех трекеров
  - 🔴 Красный `error` — если часть трекеров не синхронизировалась: «Синхронизация: X из Y (Z с ошибкой)»
  - ℹ️ Синий `info` — если нет привязанных трекеров
  - 🔴 Красный `error` — при критических ошибках (не настроена интеграция, нет авторизации)
- Обновлено во всех 4 местах: кнопка в GLONASS-карточке, кнопка на карте (десктоп/мобильный), кнопка в настройках

### Исправлен баг «Офлайн на вкладке ГЛОНАСС»

- Живой API `/api/glonass/live` теперь использует **ту же логику** определения онлайн/офлайн, что и синхронизация: порог 30 минут с последнего сообщения трекера
- Ранее использовался `connectedStatus` напрямую из Axenta, который может быть `false` при кратковременной потере связи
- Карточка трекера теперь показывает статус из `livePositions` (живые данные), а не из БД
- Бейдж статуса: «Онлайн»/«Офлайн» вместо «Активен»/«Неактивен»
- Значок в шапке карточки техники тоже обновляется через live data

## [1.7.6-beta] — 2026-05-25

### Карта не перезагружается при обновлении данных

- Убран `onRefresh()` из `fetchLiveData` — раньше при изменении позиции трекера вызывалась полная перезагрузка страницы с перерисовкой карты (тайлы, кластеры, попапы)
- Добавлено состояние `livePositions` — при каждом авто-обновлении позиция записывается в локальный state, а не триггерит перезагрузку
- Маркер перемещается через `setLatLng()` без перерисовки карты
- Живые данные (скорость, курс, высота, адрес) отображаются в карточке трекера из `livePositions`
- `livePositions` сбрасывается при закрытии карточки и смене техники

### Тихая синхронизация без спиннера

- Добавлен «тихий» режим `fetchEquipmentDetail(id, silent=true)` — обновляет данные без показа спиннера и разрушения контента
- Новый проп `onRefreshSilent` передан в `EquipmentDetailSheet`
- Кнопки «Синхронизировать» и «Обновить» на вкладке ГЛОНАСС используют тихий режим — карта и контент не перезагружаются
- Автообновление (каждые 60с) тоже обновляет открытую карточку тихо, без спиннера

## [1.7.5-beta] — 2026-05-25

### Индикатор свежести данных

- Цветовой индикатор возраста данных в заголовке карты:
  - 🟢 Зелёный — данные свежие (задержка < 30 сек)
  - 🟡 Жёлтый — задержка 30с–2м (теряет связь или Axenta отдаёт с задержкой)
  - 🔴 Красный — данные старше 2 минут (нет связи или трекер не отвечает)
  - ⚫ Серый — данные не загружены
- Текст рядом: показывает время с последнего сообщения от трекера («15с назад», «2м назад», «5м назад»)
- Логика диагностики задержки:
  - `msgTime ≈ recvTime`, оба старые → трекер не отправляет данные
  - `msgTime ≪ recvTime` (разница большая) → задержка на стороне Axenta
  - Оба свежие, но датчики не меняются → датчики не отвечают

### Живой API `/api/glonass/live`

- Новый лёгкий эндпоинт для быстрого авто-обновления
- Один запрос к Axenta (без записи в БД) — значительно быстрее `/api/glonass/sensors`
- Возвращает: позицию, датчики, диагностику (trackerLastMessage, trackerLastPosition, axentaOnline, fetchDurationMs, dataFresh)
- Автообновление датчиков на вкладке ГЛОНАСС с выбором скорости: 5с, 10с, 15с (по умолчанию), 30с, 1м, Выкл

## [1.6.0-beta] — 2026-05-25

### GLONASS: максимальная скорость обновления датчиков

Полная оптимизация конвейера обновления данных GLONASS — от API до UI. Синхронизация ускорена в 3–10 раз.

#### Новый эндпоинт `/api/glonass/quick-sync`

- Быстрое обновление датчиков **одного трекера** за 1–2 секунды
- Параллельный запрос деталей объекта и метаданных датчиков (`Promise.all`)
- Bulk `createMany` вместо N отдельных `create` (20 датчиков = 1 SQL-запрос вместо 20)
- Пропускает обратное геокодирование и статистику — только позиция и датчики
- Возвращает обновлённые данные для мгновенного обновления UI

#### Оптимизация `/api/glonass/sync`

- **Параллельная обработка трекеров** — до 5 трекеров одновременно через `Promise.allSettled` с concurrency limit
- **Fast mode** (`?fast=true`) — пропускает геокодирование и статистику, обновляет только позицию и датчики
- **Bulk `createMany`** — все датчики трекера записываются одним SQL-запросом
- **Логирование времени** — в консоли и в ответе API: `elapsedMs`, `mode: 'fast' | 'full'`
- Автообновление (60 сек) теперь использует fast mode по умолчанию

#### Кнопка быстрого обновления в карточках

- Каждая карточка техники на вкладке «Карта» получила кнопку «Обновить датчики»
- Показывает спиннер во время обновления
- Toast показывает время синхронизации: `Синхронизация: 5 из 5 (2.3с)`

#### Ожидаемое ускорение

| Операция | До | После |
|----------|-----|-------|
| Полная синхронизация (10 трекеров) | ~50 сек | ~10–15 сек |
| Быстрая синхронизация (fast mode) | ~50 сек | ~5–8 сек |
| Обновление одного трекера | ~5 сек | ~1–2 сек |
| Запись датчиков в БД (20 шт) | 20 запросов | 1 запрос |
